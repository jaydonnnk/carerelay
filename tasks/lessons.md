# Lessons

- 2026-09-21: The user is using WorkBuddy for CareRelay. Treat WorkBuddy as the primary organiser product and runtime path; do not default to CodeBuddy. Keep CodeBuddy only as an explicit fallback if the user requests it or WorkBuddy access is proven blocked.
- 2026-09-26: After Git recovery, AGENTS.md still called approved Gate 2 a draft. Root cause: the uncommitted instruction rewrite used the earlier gate snapshot. Prevention: compare gate claims with `00-status.md` and the recovered commit before presenting a commit diff.
- 2026-09-26: A patch introduced LF lines into CRLF AGENTS.md. Root cause: the patch tool preserved surrounding lines but wrote new lines with LF. Prevention: check newline counts after patching CRLF files and normalize only the edited file before diff review.
- 2026-09-26: Two read-only inventory commands failed: PowerShell Get-Item does not support -File, and rg did not expand a Windows path wildcard. Root cause: assuming shell glob and cmdlet behaviour from another command. Prevention: use Get-ChildItem -File for file inventory and rg on the directory with -g for filename filters.
- 2026-09-25: `git merge` chained with `git checkout` in one Bash call was interrupted by the sandbox (SIGTERM from the blocked reg.exe/sc.exe blacklist), leaving the object store truncated and every subsequent `git` command failing with "not a repository". Root cause: the sandbox intercepts binaries mid-pipeline and kills the whole chain, and git had begun rewriting objects. Prevention: run state-changing git operations one per command, never chained with `&&`; verify with `git status` before and after. Never run `git init` or delete `.git` to "fix" a suspected corrupt repo — escalate first.
- 2026-09-28: Switching branches (`git checkout main`) deleted **eight tracked files** from the working tree: `docs/ADDITIONAL_CHALLENGE_INFO.md`, `docs/CHALLENGE_REQUIREMENTS_JUDGING.md`, `docs/organiser-tech-load-bearing-audit.html`, `02-adversarial-review.md`, `research-workarounds.md`, and `mockups/{index,03,05}.html`. Root cause: those files existed on disk and were tracked in `main`'s target commit (`2d7ec71`) but **were absent from `gate-2-architecture`**, so checkout removed them to match the branch. They were **not in any commit reachable from the working branch**, so a naive discard would have destroyed them. **Recovery:** `git checkout HEAD -- <paths>` restored all eight, because HEAD still carried them. **Prevention:** before switching or merging branches, run `git status --short` after the checkout and read it — a non-empty list where a clean tree was expected is a stop signal, not noise. Confirm the destination commit actually contains every file the working tree holds, especially files that predate the current branch. Never run `git checkout .` or `git restore .` to "clean up" before understanding what a deletion means.
- 2026-09-28: Merge audit of `gate-2-architecture` → `main`. **Verified clean, no repair needed.** `42b5a84` is a true fast-forward with a single parent (`e77d978`), so no merge commit was created and `6c65f30` (Gate 2) is an ancestor of `main`. `gate-2-architecture` was then deleted; its four gate commits (`1cb05c8`, `c01a442`, `6c65f30`, `77ea5ed`) plus `e77d978`, `7c659b0`, `42b5a84` are all reachable from `main` (`a43a091`) and all objects verify present via `git cat-file -e`. Working tree clean, zero untracked files, no stash. Root cause of the near-miss confirmed: the eight files were **never untracked — they were tracked in `2d7ec71`, `9a1f332` and `6c65f30`**, i.e. always in `main` (and in the approved `gate-2-architecture` tip). `git checkout main` did not delete untracked content; it deleted files that branched off `main` **before** `9a1f332`, then titled the Gate 2 and Gate 3 documents using the `02-`/`03-` filenames a second time. **Correction to the earlier log entry:** the lineage was branch-off-`main`, not untracked files surviving via `main`. **Residual exposure:** (a) the working branches still fork before `9a1f332`, so the first `checkout main` from any of them will delete `docs/CHALLENGE_REQUIREMENTS_JUDGING.md`, `docs/ADDITIONAL_CHALLENGE_INFO.md` and `docs/plans/.../02-adversarial-review.md` — run `git branch <name> main` plus `git merge --ff-only main` **before** switching, or `git checkout -m main`; (b) revision-less doc filenames (`02-`, `03-`) collide by design with the `00-`-prefixed gate sequence and caused two different files to share a number — rename durable docs to slugs, not gate numbers. Prevention: before any merge, run `git merge-base --is-ancestor <tip> <target>` and `git log -1 --format=%p <tip>` — two parents means a real merge commit happened and `--ff-only` alone will not catch that after the fact.
