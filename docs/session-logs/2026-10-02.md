# 2026-10-02 (later): Gate A harness rebuilt against the real ADP schema

Jaydon obtained an ADP AppKey and ran the first-draft harness live. It returned
**PARTIAL, exit 1**, and the live traffic exposed that the harness modelled the API

doc). Rewrote `spike/gate_a/probe.py` and `test_probe.py` against the real schema.

## What the live run proved (all [verified], and better than the doc)

- Endpoint `https://wss.lke.tencentcloud.com/adp/v2/chat` is real and accepts traffic.
- **Failures arrive as HTTP 200 carrying an SSE `event: error` frame**, not as an
  HTTP 4xx. The frame: `{"Type":"error","Error":{"Code":400,"Message":"请求参数错误,
  请参阅接入文档.","RequestId":"","TraceId":"<32 hex>"},"Timestamp":"0","RecordId":""}`.
- `Error.Code` is **numeric**. `TraceId` is populated; **`RequestId` is empty** on
  this error class. The doc documents the error event but **not** its structure.
- The first draft's q1 recorded `ok: true` for a **rejected** call, because it
  passed on any HTTP 200. That is exactly the softening the gate exists to catch.

## What the doc proved (and where the first draft was wrong)

- **Auth is the `AppKey` request-body field**, not a header. The only documented
  header is `Content-Type: application/json`. **There is no second secret**, so
  `ADP_API_SECRET` is not consumed by this API at all; it is kept only so its
  redaction still covers an echoed value, and it is no longer required.
- **`ConversationId` is caller-supplied and required** (32-64 chars,
  `^[a-zA-Z0-9_-]{32,64}$`). The platform does not issue it. So Gate A Q2 is **not**
  "does ADP return a session id" but "does ADP honour a caller-supplied id across
  two calls". Reframed in the probe's docstrings as a finding, per option A.
  `RequestId` is also caller-supplied and constrained the same way.
- Other documented body fields now sent: `VisitorId`, `Contents: [{Type, Text}]`,
  `Incremental`, `Stream: "enable"` (a non-streaming call has no stream to carry
  the origin signal).

## Harness state after the rebuild

- 34 tests pass (was 17). Three mutations, each RED on exactly its own test:
  M1 header-auth reintroduced, M2 string-only error code, M3 bare-200-as-pass.
- Full suite **419 passed, 1 warning**, unchanged, so nothing outside the spike moved.
- Stale `spike/gate_a/gate_a_result.json` (first-draft, `q1 ok: true` on a rejected
  call) **deleted**; it is git-ignored (`.gitignore:37`), so it could not be committed
  but could have been misread. A fresh run regenerates it.
- Em dashes on added lines: **0** across 516. CRLF verified on both files.

## Traps reconfirmed

- PowerShell is the shell Jaydon uses, not Git Bash. `VAR=value cmd` and a trailing
  `\` continuation both fail there; use `$env:VAR = '...'`.
- The `/tmp` mismatch from the earlier note bit again: `cp` to `/tmp/probe_backup.py`
  worked from Git Bash for the restore, but a Windows-Python helper writing to `/tmp`
  would not. Repo-internal or `cygpath -w` remains the rule.

  Cloud CAM SecretId). Both flagged and rotated by him. The CAM key is account-level
