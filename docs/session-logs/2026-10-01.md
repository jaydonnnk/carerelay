## Reusable lesson

A mutation that changes an outcome *mapping* (rather than a guard) can survive a
suite that only ever asserts the guard's refusal. The guard tests here were
excellent and the outcome-mapping tests were thin. When reviewing a slice whose
contract is a table of recorded values, mutate the mapping table itself, not only
the branches that refuse.

submission is through the GitHub repository. A hidden `.workbuddy-ai/` dot-folder is
the wrong home for a required artefact, and a root `logs/` folder collides with the

### Traps hit, worth remembering

- **`pytest -q` on top of `addopts = "-q"` becomes `-qq` and hides the summary
  line.** Read "no summary" as "no result" twice before checking `pyproject.toml`.
  Use `-o addopts="" -q` to see the count.
- **A stale memory note nearly cost a commit.** `MEMORY.md` said
  `src/carerelay/demo/fixture.py` carried "a change that is not the agent's". It had
  already been committed on 30 September (`d39f9b7`); the Slice 4 policy block was
  the agent's own work. Verified by checking whether `def policy()` existed in
  `HEAD` before trusting the note. **Notes about uncommitted state go stale fast;
  verify against git.**
- **The heredoc commit succeeded while the sandbox printed a rejection notice**
  naming `reg.exe` and `sc.exe`, which the command never invoked. Read the git
  output line, not the sandbox banner.
- **The CRLF exemption is latent, not enforced.** `core.autocrlf=true` with no
  `.gitattributes` means every blob is LF and a fresh clone would check all files
  out as CRLF, including the four "exempt" ones. Do not renormalise before a push.
