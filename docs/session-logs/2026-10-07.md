### Findings that are defects

1. **The docstring's justification for the savepoint is false.** It says that
   without the rollback "the `commit` at the end of `_write` is the next thing to
   fail". Verified against PostgreSQL 17.11: `COMMIT` on an aborted transaction
   returns the `ROLLBACK` tag with **no error**, and psycopg 3's `_commit_gen`
   only skips the command when the status is IDLE and otherwise ignores the
   result. I deleted the `ROLLBACK TO SAVEPOINT` line and ran the expiry race:
   **`2 passed`**, the loser still receives `False`. The savepoint is therefore
   **not load-bearing for any observable behaviour today** — it is defensive. The
   real consequence of dropping it is that the whole transaction is silently
   discarded, which matters only once the block holds an earlier write or is
   called inside an enclosing transaction. `tasks/todo.md` line 143 words it
   correctly ("would let `_write()` commit an aborted transaction"); the docstring
   does not.
2. **`00-status.md` line 318 now contradicts itself in one paragraph**: it carries
   both the new "**F10 CLOSED 5 October 2026**" and the pre-existing "**F10 remains
   an open item in `tasks/todo.md`**". `tasks/todo.md` line 143 still lists F10 in
   the open-findings table, and this pass did not update it.
3. **RELEASE SAVEPOINT is hygiene, not correctness** — repeated `SAVEPOINT` names
   are allowed and `ROLLBACK TO` uses the most recent one, verified live.
