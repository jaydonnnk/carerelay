**A real defect in my own F4 fix, found only on the live engine.** The scratch table
was `LIKE table INCLUDING CONSTRAINTS`, which copies `CHECK` and `NOT NULL` but **not
`DEFAULT`**. The seeder omits every defaulted column on purpose (`_seed_row_for`
selects `column_default IS NULL`), so the scratch insert put `NULL` into an omitted
`NOT NULL` column (`dispositions.id`) and raised `NotNullViolation` **before any
`CHECK` ran**. The aborted transaction then refused every further statement, so the
cleanup `DROP` raised `InFailedSqlTransaction` and a third, unrelated test fell over.
Three tests failed and none was guarding anything. Fixed with `INCLUDING DEFAULTS`
plus a `SAVEPOINT` around the scratch dance so the real `CheckViolation` propagates.
Invisible without a database, which is why the review and the no-DB pass both missed it.

**The D1 mutation is now observed RED.** Removing the `_SCHEMA_APPLIED` short-circuit
fails `test_the_schema_ddl_is_not_reapplied_for_a_second_store` with `assert 1 == 0`,
